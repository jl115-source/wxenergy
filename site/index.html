import xarray as xr
import wxenergy as wx

ds = xr.open_dataset("temperature.nc")
ds = wx.standardize(ds)

# Daily climate anomalies
anom = wx.anomaly(
    ds.t2m, climatology="dayofyear"
)

# Energy-weather metric
hdd = wx.hdd(ds.t2m, base=18)

Core toolkit

Useful plumbing.
No black box.

wxenergy focuses on the repetitive processing layer between raw weather/climate data and downstream analysis. It deliberately avoids proprietary forecasting logic or trading signals.

⌁

Standardize

Coordinate names, longitude conventions, units, time dimensions, metadata, and common variable conventions.

∿

Climate statistics

Climatologies, anomalies, percentiles, rolling statistics, and temporal resampling.

◫

Spatial processing

Region masks, area means, weighted means, nearest-gridpoint matching, and regional workflows.

⚡

Energy weather

Heating and cooling degree days, degree hours, wind utilities, and general energy-weather metrics.

Project principles

Small, transparent,
boringly reliable.

01 / NATIVE

Stay close to xarray

No custom data container. Standard DataArray and Dataset objects remain at the center of the workflow.

02 / PREDICTABLE

Preserve scientific context

Coordinates, useful metadata, missing values, units, and dimensions are first-class concerns.

03 / GENERAL

Infrastructure, not alpha

Reusable processing utilities — not model-selection logic, market signals, or proprietary thresholds.

Early development

Build the boring layer once.

The first release will focus on a deliberately small, well-tested API for common weather and climate processing tasks used across energy analysis.
